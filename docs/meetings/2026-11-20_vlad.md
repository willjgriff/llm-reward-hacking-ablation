# Meeting with Vlad: SPAR reward-hacking orthogonalisation (20 Nov 2026)

Attendees: Will, Vlad. Notes as written after the meeting (not checked against a transcript).

## Summary

KTO directions barely remove refusal. Only difference-in-means on prompts works, as in the standard refusal-ablation method. That changes the blog post plan. A claim that "orthogonalisation doesn't work for reward hacking" only holds if it uses the technique that does work for refusal. Almost all the reward-hacking difference-in-means work used generated tokens rather than prompts. So the first priority is to run difference-in-means on prompt pairs for reward hacking, then outline the blog post in a Google Doc.

## Discussion

**KTO applied to refusal**
- Token positions: the hooks had been applied only to generated tokens, but the decision to refuse happens earlier, so the prompt tokens were added.
- Compliant data: the heretic dataset has none. Ethan's suggestion was used: compliant responses from the model with refusal removed.
- Vlad's alternative: generate them with a helpful-only version of the model from Hugging Face.
- Result: KTO directions barely reduce refusal. KTO LoRA does better but still falls short of difference-in-means on prompts. Only difference-in-means on prompts removes refusal well.
- It is somewhat interesting that a KTO direction partly works for reward hacking but not for refusal.

**What this changes**
- Most of the techniques that failed for reward hacking also fail for refusal. So a negative result is only convincing if it uses a method that works for refusal; otherwise it looks like a bad orthogonalisation setup.
- Redo the blog post experiments with difference-in-means on prompts, copying the standard refusal method (Arditi et al.) as closely as possible.
- Prompt-pair difference-in-means probably rules out some environments, but not the grader.
- If it reduces reward hacking to some extent: proceed with the planned comparison against KTO on sample efficiency and bad-data tolerance.
- If not (expected): write the blog post as "orthogonalisation does not work for removing reward hacking".

**Prompt pairs for reward hacking**
- Possible vs impossible task prompts. For example, in the terminal env, take the rollout prefix up to the step where the verifier's contents show the task is impossible, and pair it with the same prefix modified so the verifier is possible.

**Is the negative result solid?**
- Vlad asked whether enough has been tried to claim no direction exists, rather than not having tried hard enough.
- Will's view: the configuration space (token positions, layers, data) is huge, but most things that had a real chance have probably been tried.
- Almost everything so far used difference-in-means on generated tokens, often resampling the same prompt. Very little compared possible vs impossible prompts.
- A finding that difference-in-means on responses doesn't work is still worth writing up, even though the same is true for refusal. But prompt-based difference-in-means needs more experiments first.

**Hook vs weight editing**
- In Will's experience, projecting out with a hook and editing the weights behave about the same.
- Use whichever is simpler for now, and run every final experiment both ways at the end.

## Decisions
- Switch the blog post experiments to difference-in-means on prompts, following the standard refusal method.
- If that gives the expected negative result, publish the blog post as a negative result.
